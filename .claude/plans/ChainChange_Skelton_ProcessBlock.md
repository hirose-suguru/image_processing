# ChainChange_Skelton_process_block.md - 機能改善計画

## Context

現在の画像カラー置換ツール (`public/index.html`) は、画像全体から選択した色を別の色に一括置換する機能のみ。以下3つの課題がある：

1. 色を変えた後にさらに変えたい場合、変換済みの色を再選択する必要があり手間がかかる
2. 色を透過にする機能がない（背景除去等に不便）
3. 画像全体ではなく、特定の囲まれた領域だけを変換したいケースに対応できない

## 実装順序（簡単な順）

---

### 1. 透過化機能 (Feature ii) - 最も簡単

**概要**: 選択した色のピクセルを透明（alpha=0）にするボタンを追加

**UI変更**:
- 「カラー置換」ボタンの横に「透過化」ボタンを追加
- 既存のボタンと同じ `flex gap-2` コンテナ内に配置

**JS変更**:
- `makeTransparent()` 関数を新規追加
- 既存の `replaceColor()` とほぼ同じループだが、色の置換ではなく `data[i+3] = 0` でアルファを0に設定
- `isSimilarColor()` で既存の±5トレランスを再利用
- canvasクリック時に `transparentBtn` も有効化

**対象ファイル**: `public/index.html`

---

### 2. 連鎖変換モード (Feature i) - 中程度

**概要**: ONにすると、A→B変換後に `selectedColor` が自動的にBに更新され、続けてB→C→D...と連鎖的に色を変えられる

**UI変更**:
- カラー設定パネル内にチェックボックス「連鎖変換モード」を追加
- 説明文: 「ONの場合、置換後にクリックした色が自動的に新しい色に更新されます」

**JS変更**:
- `chainModeToggle` の参照を追加
- `replaceColor()` の置換完了後に以下を追加:
  ```
  if (chainModeToggle.checked && replacedCount > 0) {
      selectedColor を newColor に更新
      UI表示（カラーサンプル、HEX、RGB）も連動更新
  }
  ```
- 透過化（Feature ii）では連鎖モード非適用（透過後に「次の色」が無意味なため）

**注意点**:
- `replacedCount === 0` の場合は更新しない（何も変わってないため）

**対象ファイル**: `public/index.html`

---

### 3. ピン置換モード (Feature iii) - 最も複雑

**概要**: 画像上にピンを配置し、ピンから連結した同色領域のみを置換。黒い線などの境界で止まる。

**UI変更**:
- 「置換モード」選択パネルを新規追加（ラジオボタン）
  - 「全体置換」（現在のモード、デフォルト）
  - 「ピン置換（連結領域のみ）」
- ピンモード時のみ表示:
  - 説明テキスト
  - 「境界しきい値」スライダー（10〜100、デフォルト30）- RGB空間のユークリッド距離
  - ピン位置情報表示
- canvas上にピンマーカー（赤い十字+円）を描画

**JS変更 - 状態管理**:
- `pinPosition = null` （ピン座標）
- `currentReplaceMode = 'all'` （'all' or 'pin'）
- `canvasBackup = null` （ピンマーカー描画前のImageData保存用）

**JS変更 - canvasクリックハンドラ分岐**:
- 全体モード: 既存動作（色選択のみ）
- ピンモード: 色選択 + ピン配置 + マーカー描画

**JS変更 - Flood Fill アルゴリズム（BFS）**:
```
floodFillReplace(startX, startY, targetColor, newColor, newAlpha, boundaryThreshold):
  1. visited配列（Uint8Array）で訪問済み管理
  2. キューにピン位置を追加
  3. BFSループ:
     - ピクセルがtargetColorと類似 → 色を置換
     - 4方向の隣接ピクセルを探索
     - 隣接ピクセルとtargetColorのRGBユークリッド距離 > boundaryThreshold → 境界として停止
  4. 置換済みImageDataをcanvasに反映
```

**パフォーマンス対策**:
- キューは標準JS配列 + headインデックス（`shift()`回避でO(1)デキュー）
- visited は `Uint8Array` でメモリ効率化
- ピクセルインデックスを `y * width + x` の単一整数でエンコード（メモリ半減）
- 既存パターンの `setTimeout(..., 100)` でUI応答性確保
- Web Workerは単一ファイル構成を維持するため初期実装では不採用

**境界しきい値の意味**:
- 値30 = RGB距離30以内の色は通過、それ以上は境界
- 黒線(0,0,0) vs 白(255,255,255) = 距離441 → 確実に停止
- パステル境界には高めのしきい値が必要

**統合ポイント**:
- `replaceColor()` にモード分岐を追加
- `makeTransparent()` にもピンモード対応を追加
- ダウンロード/コピー時は `removePinMarker()` でマーカーを一時除去してから出力
- 連鎖変換モードとの併用: ピン置換後もselectedColorが更新され、同じピン位置で連鎖可能

**対象ファイル**: `public/index.html`

---

## 検証方法

1. **透過化**: 画像を読み込み → 色をクリック → 「透過化」ボタン → ダウンロードしたPNGで透過部分を確認
2. **連鎖変換**: A色をB色に変換 → 連鎖モードON → B色をC色に変換（再クリック不要で動作すること）
3. **ピン置換**: 黒線で囲まれた領域内の色をクリック → ピンモードで置換 → 囲みの外の同色が変換されていないこと
4. **組み合わせ**: ピンモード + 連鎖変換、ピンモード + 透過化が正常動作すること
